Lightning Queries lab: UI mockups

Three static mockups for CSE Day 2026-11-06. Fake data. No backend. Compare them and select one.

1. Race view mockup-race.html · Lab 2

Two lanes side by side: Lightning Tables and Tableflow. Push "Write marker". Each lane shows a stopwatch, a poll log with one dot per poll, and a large "visible after" time. Lightning stops at about 1.5 s. Tableflow keeps polling every 30 s and stops after some minutes. A list of past runs is below. Use the speed switch (1x, 10x, 60x) to make the demo shorter. The times always show lab time.

2. Table view mockup-upsert.html · Lab 3

Three small live tables for key 9001: the append table lq_orders (every event adds a row), the Lightning upsert table lq_orders_latest (one row, the price cell flashes when it changes) and the Tableflow lq_orders_latest (old price with an OLD badge until it catches up). Push "Write UPD-n with price p". A timeline at the bottom shows, per write, when each table showed it. The page starts with UPD-1 and UPD-2 done, so you can write UPD-3 at once.

3. Combined lab dashboard mockup-dashboard.html · Labs 1 to 3

One page with tabs for Lab 1, Lab 2 and Lab 3, and a status bar on top like the lab doctor (Cluster, RTCE, Tableflow, Feed). Lab 1 has a SELECT box, a result grid and the query time. Lab 2 is a compact race with two bars on a 0 to 5 min axis. Lab 3 shows the current price per table as large numbers, with an event log.
Each file opens with a double click. No network access. The real app will be a Python http.server that polls tools/lq.py every 1 s and tableflow/tableflow_query.sh every 30 s.
